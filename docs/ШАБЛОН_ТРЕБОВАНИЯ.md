# Шаблон требования

Скопируйте этот блок в канонический документ области. Одно требование — одна
проверяемая мысль. Формулировка «сделать правильно» или перечень нескольких
ограничений в одном пункте не годятся для независимой проверки.

```markdown
### <ID> · <короткое название>

| Поле | Значение |
| --- | --- |
| Статус | подтверждено / рабочая гипотеза / спорно / отменено |
| Владелец решения | кто может подтвердить или изменить правило |
| Источник | документ, версия, лист/страница или слова человека с датой |
| Требование | одно точное условие без описания реализации |
| Единица и точность | рубли / доля ставки / месяц; округление и допуск |
| Допустимо | минимум два граничных примера |
| Недопустимо | минимум два контрпримера |
| Если данных нет | отказ / вопрос пользователю / явное значение по умолчанию |
| Тяжесть | error / warning / info |
| Код исполнения | файл и функция или «нет» |
| Независимый аудит | файл и функция или «нет» |
| Случаи harness | положительный и отрицательный номера или «нет» |
| Отображение | где человек увидит нарушение и к каким данным перейдёт |
| Открытые вопросы | что ещё нельзя однозначно реализовать |
```

## Критерии готовности

- источник и статус названы;
- границы правила выражены числами или однозначными условиями;
- определено поведение при пропуске и конфликте данных;
- код не является единственным местом, где правило существует;
- готовый результат проверяется независимо, если это возможно;
- есть тест, который обязан пройти, и тест, который обязан упасть;
- ошибка содержит ID, объект, период, факт и ожидаемое значение;
- пробелы покрытия записаны явно.

## Пример запроса агенту

> Разбери перечисленные требования по одному. Для каждого создай карточку по
> `docs/ШАБЛОН_ТРЕБОВАНИЯ.md`, найди реализацию и существующие проверки. Не
> считай код доказательством требования. Составь матрицу покрытия и отдельно
> перечисли противоречия и отсутствующие источники. Для подтверждённых числовых
> правил добавь независимый аудит готового результата и положительный и
> отрицательный случаи harness. Спорные правила не реализуй догадкой.

Такой запрос можно давать Codex или Claude для аудита всей области, разбивая
большой список на небольшие группы с отдельным ревью изменений.
