## Исследование референсов

**Анти-паттерн «ИИ-дизайна»** (сводка по публикациям о "AI slop design"):
фиолетово-голубые градиенты и лавандовые заливки; серая рамка 1px на каждой
карточке; цветная полоса 3–5px слева; бейджи-пилюли с рамками; разделители-точки
«·» в подписях; три карточки в ряд; одинаковые скругления везде; тёмная тема
рефлексом. Рекомендации: разделение пространством и сдвигом фона вместо рамок,
таблицы вместо карточек, один акцентный цвет, рамки только там, где несут смысл.

Источники: [vibecodekit.dev/ai-slop-design](https://vibecodekit.dev/ai-slop-design),
[smoothui.dev/blog/ai-design-slop](https://smoothui.dev/blog/ai-design-slop),

## Замеры производительности решателя

Последовательные запуски `fot-planner solve`, эта машина:

| Кейс | Время | Статус |
|------|-------|--------|
| 1 сотрудник, 2 договора (uc15) | 2 с | OPTIMAL |
| 3 сотрудника, 2 договора (uc12) | 3,4 с | OPTIMAL |
| uc12 + 4 сотрудника (7, 2 договора) | 14,9 с | OPTIMAL |
| 10 сотрудников, 2 договора (ГОЗ+ВБ) | 11,1 с | OPTIMAL |
| 6 сотрудников, 3 договора | 18,4 с | OPTIMAL |
| 8 сотрудников, 3 договора | 142,8 с | OPTIMAL |
| 10 сотрудников, 3 договора | > 240 с | таймаут |
| 5 сотрудников, 4 договора | > 150 с | таймаут |
| 100 сотрудников, 20 договоров | > 600 с | таймаут |

Выводы. Главный фактор времени — число договоров, а не сотрудников: два
договора держат десяток людей за секунды, четыре не тянут и пятерых. Второй
фактор — зазор между фондами и потребностью: избыток в несколько процентов
замедляет решение на порядки (решатель комбинаторно выбирает, что не осваивать);
входы с точным раскроем решаются быстро. Кандидаты для задачи производительности:
фиксация схемы выплат как эвристика, декомпозиция по сотрудникам, mipgap,
ослабление целочисленности ставок.

## Критик, раунд 1 (по версии-базлайну)

14 находок; ключевые: рассинхронизация сумм между разделами (три разных
«освоено»), выдуманные ФИО в сверке, нарушение собственных лимитов в карточках
сотрудников, ошибка арифметики в вопросе агента, поступления грантов вне срока
договора, drag-and-drop уводил со страницы, скрытые прокруткой колонки штатки.
Решение: вместо точечных заплат — переход на единый источник данных
(реальный результат решателя), закрывающий класс проблем целиком.

## Архитектура v2

- Все разделы рендерятся из одного JSON (вход + результат `fot-planner`).
- Кнопка «Рассчитать план»: POST `/api/solve` через `serve.py` — настоящий
  запуск решателя; без сервера — встроенный результат с честной подписью.
- Сценарии агента 4 — три реально просчитанных варианта входа.
- Разбор невыполнимости агента 3 — реально невыполнимый вариант входа.
- Драг-энд-дроп на зонах загрузки перехватывается.

## Критик, раунд 2 (по новой сборке)

12 находок, все закрыты: невидимые за обрезкой колонки на узких экранах
(min-width:0 для ячейки сетки), два времени расчёта (внутреннее время решателя
подписано отдельно от полного цикла), оклад «специалиста» приведён к справочнику
решателя (40 400), вопрос по нераспознанному файлу встаёт в очередь только после
указания макета, кандидат должности заменён на существующий в справочнике,
источники вопросов совпадают с таблицей документов, канонический список листов
книги берётся из фактического файла результата, контраст вторичного текста
поднят до нормы AA, инициалы и даты приёма сделаны правдоподобными, склонения
и десятичные запятые выровнены.

## Итоговое состояние

- Базовый кейс: 10 сотрудников, договоры ГОЗ (поквартальные транши) и внебюджет,
  потребность 12 391 800 ₽, решение HiGHS 12,2 с, OPTIMAL, дефицит 0,
  фонды освоены полностью. Один сотрудник принят с апреля — месяцы плана
  различаются, звезда 160 000 ₽ закрывается через 124 и приказ.
- Сценарии — реальные прогоны: −15 % ГОЗ → адресный дефицит 1 806 480 ₽;
  увольнение с 30.06 → высвобождение 522 001 ₽; задержка транша → честный
  INFEASIBLE за 3,6 с. Разбор невыполнимости — реальный INFEASIBLE за 2,8 с.
- Кнопка «Рассчитать план» через serve.py запускает настоящий решатель
  (проверено в браузере: 12,3 с, отметка «локальный решатель подключён»);
  без сервера используется встроенный результат с честной подписью.
- Проверки браузером: 0 ошибок JS, 0 горизонтальных переполнений на 1280 и 700,
  числовая согласованность разделов подтверждена инструментально.

## Реальная загрузка документов

Раздел «Извлечение данных» перестал быть инсценировкой. Новый модуль
`docs/ui/extract.py` — детерминированный якорный разбор: опознание листов по
маркерам, извлечение показателей, проверка расчётными соотношениями форм.
`serve.py` получил `/api/upload` (свой разбор multipart: в Python 3.14 модуль
`cgi` удалён) и `/api/chat`.

Проверено на настоящих файлах заказчика: `РКМ по ГОЗ_ОБРАЗЕЦ.xlsx` — опознана
форма 9д; `Структура_цены_ОБРАЗЕЦ_расширенный.xlsx` — опознаны «Структура цены»
и «Расшифровка ФОТ», честно отмечено, что это образец без значений, и названо,
каких данных не хватает для расчёта.

Сквозной цикл (скриптом и в браузере): загрузка → правка `E001 зарплата 145000`
в чате → расчёт настоящим решателем 9,3 с → выплачено 12 211 800 ₽ при
потребности 12 211 800 ₽, сотрудник закрыт полностью.

По дороге исправлены две содержательные ошибки: пропорциональное
масштабирование фондов давало INFEASIBLE на стадии оптимизации приказов —
заменено точным раскроем (штатная часть в пределах приказа 2556 на договор
с окладом, остаток на договор с надбавкой 124 и приказом); фонд считался на
12 месяцев без учёта даты приёма — теперь по фактическому периоду работы.
