Свойства объекта: «свойство — значение — источник», каждое значение правится по клику редактором своего типа.

**Что даёт потребитель:** `groups` (`title` и `rows`) или плоский `rows`, обработчик `onCommit(key, value)` и, если источник кликабелен, `onOpenSource(row)`. Строка: `key`, `label`, `type`, `value`, `options` для выбора, `source`, `issue` для проблемы с источником, `readonly`, `required`, `hint`, `unit`, `digits`.

## Типы значений

| `type` | Редактор | Формат отображения |
| --- | --- | --- |
| `text` | поле ввода | как есть |
| `number` | числовое поле | `12` + `unit` |
| `stepper` | «−» и «+» с шагом `step`, стрелки ↑ ↓ | `12 мес.` |
| `money` | числовое поле | `7 000 000 ₽` |
| `date` | выбор даты | `10.09.2026` |
| `daterange` | две даты и «Готово» | `01.01.2026 — 31.12.2026` |
| `select` | список | подпись варианта |
| `boolean` | флажок на месте значения, щелчок сохраняет | флажок |
| `multiselect` | чипы с «×» плюс список с галочками | чипы через запятую |
| `readonly` | нет | значение приглушённой подписью строки |

## Порядок свойств

**Свойства группируются по смыслу, а не по алфавиту.** Алфавит разносит «Срок действия», «Выплата оклада до» и «Выплата надбавок до» по разным концам списка, хотя экономист сверяет их вместе. Рабочие группы: идентификация, режим работы, сроки, деньги и начисления. Внутри группы — в порядке заполнения, а не по алфавиту.

Группы объявляются заголовками `column-head` в `ink-muted`, без рамок и без отдельного фона: их отделяет отступ и линия `border-subtle`.

## Правила

- Ширины колонок фиксированы: свойство 30%, значение 44%, источник 26%. Значения выстраиваются в столбик и читаются одним движением глаза. В fot-planner графы «Источник» у свойств договора нет (решение владельца 29.09.2026): источник известен у договора целиком, а не у поля, и подпись вводила в заблуждение; там две графы — 30% и 70%, без шапки.
- Высота строки — `row-md`; чересполосицы нет, строку выделяет только наведение (`surface-hover`) и правка (`surface-selected`).
- Приглашение к правке видно до клика: при наведении на строку значение получает пунктирное подчёркивание `border-control`. Незаполненное значение показывается словом «Указать» в `ink-muted`, при наведении — в `accent`.
- Enter сохраняет, Esc отменяет, Tab переходит к следующему значению. `daterange`, `stepper` и `multiselect` закрываются кнопкой «Готово» или Enter.
- Отдельной кнопки «Добавить» у множественного выбора нет: набор чипов сам по себе кликабелен и при наведении подчёркивается пунктиром, как любое другое значение. Лишняя пунктирная кнопка внутри строки спорит с этим общим приглашением и утяжеляет строку.
- Величины с естественной единицей и мелким шагом (месяцы, ставки, штатные единицы) — `stepper`, а не список: список из двенадцати пунктов заставляет искать нужный, а «−»/«+» с шагом 1 и стрелки ↑ ↓ меняют значение на один шаг там же. `min`, `max` и `step` задаются явно.
- Рассчитанные и унаследованные свойства помечаются `readonly`: без подчёркивания и без курсора текста. Правится только то, что вводит человек.
- **Колонка «Источник» — не украшение, а доказательство.** Она отвечает на вопрос «откуда взялось это число» и потому кликабельна: клик открывает файл или реквизит.
- Если значение не найдено, это состояние источника, а не значение: `issue` выводит `Status` («Не найдено в документах»), а само значение остаётся пустым или «Нет». Красная точка без слова смысла не передаёт.
- Обязательные незаполненные свойства помечаются `required` и выносятся наверх фильтром «Только незаполненные»: в договоре на 17 свойств глазами их не найти.
- Подтверждайте правку видимо: пересчитанная сумма, обновлённый статус, короткое уведомление.
