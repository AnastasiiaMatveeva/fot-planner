# Макет интерфейса планирования ФОТ

Семь экранов интерфейса в виде исходников доски Claude Artifacts (тип Design).
Не приложение и не код `app/`: это предложение по интерфейсу, которое
обсуждается с владельцем продукта в комментариях к доске.

- **Статус:** черновик, обсуждается. Решением продукта не является.
- **Источник:** доска <https://claude.ai/artifact/6eU6vA7uyYqUKZ5NxCgf83>,
  версия 72 от 17.09.2026. Файлы здесь — копия опубликованных.
- **Правила, которым подчиняется:** `docs/ИНТЕРФЕЙС.md` (UI-001…UI-008),
  свод правил решателя `docs/ПРАВИЛА_РЕШАТЕЛЯ.md`, источники величин
  `docs/ИСТОЧНИКИ.md`.

## Как открыть

```bash
cd docs/ui/mockup/html && python -m http.server 8777
```

Дальше `http://127.0.0.1:8777/Main.html`; между экранами есть ссылки. Двойным
щелчком из проводника не открывать: страницы подключают `html/support.js`, а из
`file://` он не грузится.

`html/` собран из `project/` дословно — та же разметка и те же стили. Отличий
три: стиль переехал из `<helmet>` в `<head>`, ссылки `X.dc.html` стали `X.html`,
и подключена `support.js` — самодельная среда, которая разворачивает `sc-for`,
`sc-if` и подстановки `{{ }}`. На доске это делает её собственная среда.

Одно расхождение с доской: `onChange` привязан к событию `change`, то есть
срабатывает по уходу из поля, а не на каждой букве.

## Кому отдавать в работу

`ЗАДАНИЕ.md` рядом — что читать, чего требовать от таблиц, какие термины откуда
взяты, что показано честно нереализованным и чего додумывать нельзя.

## Открытые вопросы, поднятые макетом

Записаны, а не решены: каждый меняет расчёт или документ, а не разметку.

| Вопрос | Как сейчас | Где обсуждается |
| --- | --- | --- |
| Свой срок выплат у каждого вида надбавки | у договора две даты: `salary_payment_deadline` и общий `allowances_payment_deadline` на 120/122/124/152/приказ (`contract_calendar.py`) | ветка 814d71dd |
| Правила по категориям договоров | `goz_labor_tolerance` 5 % и `goz_average_salary_limit` 112 261 ₽ — общие настройки с именами по ГОЗ, а не свойства категории | ветка f2f93c7b |
| «Приоритет 2030» — свойство договора или категории | `ИСТОЧНИКИ.md`: свойство договора, планом не переопределяется (решение владельца 16.09.2026); макет предлагает свойство категории | ветка 65b791cd |
| Настройка порядка стадий оптимизации | порядок задан в коде, допуск 1 ₽ на стадию; макет предлагает настройку стрелками | раздел «Контроль» на экране плана |

## Что макет изменил в терминах

| Было в макете | Стало | Почему |
| --- | --- | --- |
| «Вид договора» + отдельная графа «ГОЗ» | «Категория договора» | ГОЗ и так значение вида; две графы про одно |
| «Приоритет исполнения» | «Приоритет 2030» | имя из правила 12 свода правил; «исполнения» — выдумка, признак не про очерёдность |
| «В расчёте» | «Учитывать в расчёте» | графа отвечает «учитывать ли этот договор», а не «идёт ли расчёт» |
| «Промежуточные итоги по графе» | «Группировать по этой графе» | термин 1С; в Excel «промежуточные итоги» — другое действие |
| «Состояние пакета», «Не хватает документов» | убраны | оценка разбора, а не факт договора |
