# Демонстрационные материалы

| Файл | Что это |
|------|---------|
| `prototype.html` | Интерактивный прототип интерфейса на реальном результате решателя |
| `about.html` | Схема и описание сервиса: семь ИИ-агентов, оптимизатор, вход, выход, ограничения |
| `serve.py` | Локальный сервер: кнопка «Рассчитать план» запускает настоящий `fot-planner` |
| `demo_input.xlsx` | Демонстрационный входной файл |
| `demo_result.xlsx` | Результат решателя для этого входа |
| `archive/` | Прежние версии страниц |

## Два режима показа

**Без сервера.** Двойной клик по `prototype.html`. Загрузка файла сообщит, что
сервер не запущен, и покажет паспорт демонстрационного файла; кнопка
«Рассчитать план» использует встроенный результат — те же числа, что в
`demo_result.xlsx`. Интерфейс не изображает разбор, которого не было.

**С настоящим расчётом и загрузкой документов.** Из корня репозитория:

```bash
.venv/Scripts/python.exe docs/ui/serve.py
```

Открыть `http://127.0.0.1:8760/prototype.html`. Появляются три возможности:

1. **Загрузка файла.** Перетащите или выберите `.xlsx` / `.xlsm`. Файл читается
   по-настоящему: `extract.py` опознаёт листы по маркерам («сотрудники»,
   «договоры», «СТРУКТУРА ЦЕНЫ», «Расшифровка ФОТ», форма 9д), извлекает
   показатели и проверяет расчётные соотношения самих форм
   (чел.-мес × стоимость = итог, сумма поступлений = ФОТ). На экране —
   журнал: что за лист, сколько строк извлечено, где не сошлось.
2. **Чат правок.** Команды: `покажи договоры`, `покажи сотрудников`,
   `E001 зарплата 150000`, `C_GOZ фот 5200000`, `рассчитай`.
   Правка меняет паспорт договора; при сборке входа фонды пересобираются
   точным раскроем под новую потребность.
3. **Настоящий расчёт.** Кнопка отправляет паспорт в `fot-planner solve`
   и возвращает свежий результат; в шапке отметка «локальный решатель
   подключён», в статусе — фактическое время.

Свободные формулировки правок (не по шаблону команд) разбирает LLM-слой —
в этой сборке он отключён, агент честно сообщает об этом.

Остановить сервер: `Ctrl+C`.

## Масштаб демонстрационного кейса

Кейс подобран по фактической производительности модели (замеры 13.08.2026,
последовательные запуски на этой машине):

| Сотрудников | Договоров | Время решения |
|-------------|-----------|---------------|
| 1 | 2 | 2 с |
| 3 | 2 | 3,4 с |
| 7 | 2 | 14,9 с |
| 10 | 2 | 11,1 с |
| 6 | 3 | 18,4 с |
| 8 | 3 | 142,8 с |
| 10 | 3 | больше 240 с |
| 5 | 4 | больше 150 с |
| 100 | 20 | больше 600 с |

Два вывода. Во-первых, время растёт круто по числу договоров: два договора
держат десяток сотрудников за секунды, четыре договора не тянут и пятерых.
Во-вторых, фонды должны сходиться с потребностью: входы, где фонд превышает
потребность на несколько процентов, решаются на порядки дольше — решатель
комбинаторно выбирает, что не осваивать. Демонстрационный кейс: 10 сотрудников,
2 договора. Производительность модели — отдельная инженерная задача.

## Правка

Страницы самодостаточны: разметка, стили, скрипт и данные в одном файле.
Данные лежат в `<script id="demo-data" type="application/json">` —
их пересборка из свежего результата: `scratchpad/pack.py` сессии
либо вручную через `result2json.py`.
