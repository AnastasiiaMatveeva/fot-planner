# Карта знаний проекта

Этот файл — вход в документацию для человека и агента. Его задача — показать,
где лежит актуальное правило и насколько ему можно доверять. Полный текст
требований не дублируется между файлами.

## Приоритет источников

При расхождении используется следующий порядок:

1. явное текущее решение владельца продукта;
2. подтверждённая карточка в каноническом документе;
3. первичный документ экономиста с версией и страницей/листом;
4. реализованное поведение и тесты как свидетельство текущего состояния;
5. обзор, исторический аудит или бывшая локальная память агента.

Код показывает, что сервис делает сейчас, но сам по себе не доказывает, что
это требование. Спор не разрешается выбором наиболее удобной версии: он
записывается в раздел открытых решений.

## Вспомогательные и исторические материалы

Эти файлы полезны как доказательство и история, но не должны молча создавать
новое требование:

- `README.md` в корне — формат входа, CLI и обзор реализации;
- `docs/CONSISTENCY.md` — снимок согласованности слоёв;
- `docs/MODEL_REVIEW.md` — аудит модели и вопросы экономистам;
- `docs/ISSUE_UI.md` — устройство списка замечаний;
- `docs/CONTRACT_REMAINDERS.md` — цель «меньше договоров с остатком ФОТ»; порог
  1 000 ₽ снят 11.09.2026;
- `docs/ui/` — модули разбора и шаблон входа, которыми пользуется приложение,
  и схема сервиса `about.html`; прототип удалён 11.09.2026.

Если исторический файл нужен для действующего правила, канонический документ
ссылается на его точный раздел и указывает статус решения.

## Правило обслуживания

Новый `.md` создаётся только тогда, когда у него есть отдельный владелец
смысла. При изменении требования обновляются его карточка, независимая
проверка и harness. Если меняется только состояние конкретного дня, создаётся
датированный снимок и он не объявляется каноническим.
