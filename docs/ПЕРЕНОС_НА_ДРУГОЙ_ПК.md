# Перенос сервиса на другой компьютер

После переноса проектных правил в репозиторий отдельно копировать память Claude
не требуется. Перенос состоит из кода, секретов и, при необходимости, живого
экземпляра данных.

## 1. Код и окружение

Нужны Git и Python 3.11. Для текущей рабочей ветки:

```bash
git clone -b demo-ui https://github.com/AnastasiiaMatveeva/fot-planner.git
cd fot-planner
py -3.11 -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[web,llm,dev]"
```

Имя `.venv` важно: переносимые хуки Claude Code используют этот путь.

В git приезжают `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`,
`.claude/launch.json`, документация, harness и демо-набор.

## 2. Секреты

`.env` не хранится в git. Его надо передать защищённым способом и положить в
корень проекта. Какие переменные бывают, описано в `.env.example`. Агент не
должен создавать отсутствующие ключи или выводить их в чат. Локальная модель
доступна только из сети, где виден её адрес; DeepSeek
требует соответствующий ключ.

`.claude/settings.local.json` также не переносит знания о проекте. Его можно
создать заново для локальных разрешений и путей конкретного компьютера.

## 3. Живые данные

`app/data/` игнорируется git. В нём находятся база, загрузки, предпросмотры и
результаты конкретного экземпляра приложения. Есть два честных режима:

- новый пустой экземпляр — каталог не копируется;
- продолжение существующего экземпляра — при остановленном сервисе переносится
  весь `app/data/` одной согласованной резервной копией.

Нельзя собирать базу и uploads из копий разных моментов. Рабочие документы могут
содержать персональные или договорные данные, поэтому обычный git для них не
подходит.

Автоматической команды экспорта экземпляра в проекте пока нет. До её появления
копирование `app/data/` остаётся отдельной операционной процедурой.

## 4. Проверка

На новом компьютере агент сначала читает `AGENTS.md` и `docs/README.md`, затем
проверяет наличие `.venv`, `.env` и выбранного режима `app/data/`. Ничего из
отсутствующего он не выдумывает.

```bash
.venv/Scripts/python.exe scripts/check.py --quick
```

Известные красные случаи и их причины читаются из `harness/known_red.txt`, а не
из старого сообщения или памяти пользователя.
