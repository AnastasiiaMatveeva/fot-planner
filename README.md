# fot-planner

`fot-planner` планирует фонд оплаты труда по договорам и сотрудникам. Сервис читает входной Excel, строит помесячный план выплат, проверяет ограничения по договорам, должностям, трудоёмкости и лимитам оплаты, а затем выгружает результат обратно в Excel.

Основной пользовательский сценарий рассчитан на финансиста или проектного администратора: заполнить шаблон, запустить расчёт, посмотреть итоговые листы и при необходимости пересчитать план с фиксациями.

## Что Поддерживает Сервис

- Планирование выплат на год по сотрудникам, договорам и месяцам.
- Виды выплат: оклад, 120, 122, 124, 152 и стимулирующая выплата приказом.
- Разные правила договоров: сроки действия, сроки выплат, разрешённые виды выплат, ГОЗ.
- Поступления по договорам через `фот_по_месяцам`: договоры по строкам, месяцы по столбцам.
- Открытые ставки: основное место и совместительство, включая доп. ставку до установленных лимитов.
- Взаимозаменяемые должности через группы из листа `лимиты_по_должностям`.
- Плановую трудоёмкость по договорам в чел.-мес. с контролем факта по строкам и группам.
- Назначение сотрудника на совместимую должность договора: если на договоре важна должность `программист`, сотрудник `инженер` из совместимой группы может быть показан в результате как `0.5 программист`.
- Лимиты по должностям: справочный оклад, П2556, П4, БЭП для ГОЗ.
- Минимизацию административной сложности: меньше смен договора, меньше дробления выплат, меньше лишних связок сотрудник-договор.
- Дополнительные ручные листы для сложных сценариев, если они вручную добавлены во входной файл.

## Установка

```bash
cd fot-planner
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

Требуется Python 3.10+. Оптимизационная модель использует Pyomo и MIP-решатель.

## Быстрый Старт

```bash
# 1. Создать входной шаблон
fot-planner init-template -o data/input.xlsx

# Вариант для демонстрации: macro-enabled шаблон с кнопкой «Запустить расчет»
fot-planner init-template -o data/input.xlsm

# 2. Заполнить Excel
# Основные листы: сотрудники, договоры, трудоемкость_по_договорам,
# фот_по_месяцам, настройки, лимиты_по_должностям.

# 3. Рассчитать план из консоли
fot-planner solve -i data/input.xlsx -o data/result.xlsx

# 4. При необходимости пересчитать с учетом листа «План выплат» из прошлого результата
fot-planner solve -i data/input.xlsx -o data/result.xlsx --plan data/result.xlsx
```

## Новый Шаблон Excel

Новый файл, который создаёт `fot-planner init-template`, содержит только основные рабочие листы:

- `сотрудники`
- `договоры`
- `120_надбавка`
- `трудоемкость_по_договорам`
- `фот_по_месяцам`
- `настройки`
- `лимиты_по_должностям`

Если указать расширение `.xlsm`, шаблон дополнительно получает лист `Запуск` с кнопкой `Запустить расчет`. Кнопка сохраняет текущую книгу, ищет `.\.venv\Scripts\fot-planner.exe` в текущей папке и выше по дереву, запускает оптимизатор и сохраняет результат рядом с файлом как `*_result.xlsx`. Для создания такого шаблона на машине сборки нужен установленный Microsoft Excel и включенная настройка Excel `Trust access to the VBA project object model`; для обычного нажатия кнопки пользователю достаточно разрешить макросы в книге.

Из генерации нового шаблона убраны редко используемые ручные листы:

- `минимальные_остатки`
- `фиксация_фот_по_месяцам`
- `ручные_назначения`
- `ручные_запреты`

Загрузчик ожидает русские названия листов из текущего формата. Старые английские имена листов не поддерживаются.

## Требования К Входному Файлу

Входной файл должен быть Excel-книгой `.xlsx` или `.xlsm`. Минимально нужны листы `сотрудники` и `договоры`; остальные листы уточняют правила расчёта. На практике лучше использовать шаблон и заполнять все основные листы, даже если часть таблиц остаётся пустой.

Имена листов в новом шаблоне русские. Загрузчик ожидает текущие русские имена листов и колонок из шаблона.

### `сотрудники`

Описывает штатные строки сотрудников.

Основные колонки:

- `код строки` — уникальный идентификатор строки сотрудника. Можно использовать табельный номер или табельный номер с суффиксом, если у одного человека несколько строк.
- `фио` — имя сотрудника для отчётов.
- `должность` — штатная должность. По ней определяется группа взаимозаменяемости и справочный оклад.
- `подразделение` — справочная колонка.
- `ставка` — штатная ставка в этой строке, например `1.0`, `0.5`, `0.25`.
- `тип занятости` — `основное`, `совместительство` или пусто/`auto`.
- `категория занятости` — `основной`, `студент`, `аспирант`.
- `зарплата` — полная месячная сумма, которую нужно выплатить сотруднику.
- `дата начала`, `дата окончания` — период активности сотрудника.
- `разрешенные договоры` — опциональный список договоров, на которые можно назначать сотрудника.
- `запрещенные договоры` — опциональный список договоров, на которые сотрудника назначать нельзя.

Если должность сотрудника есть в `лимиты_по_должностям`, сервис подтягивает группу взаимозаменяемости, уровень и справочный оклад. Если должность не найдена, часть ограничений по совместимости и окладу может не сработать как ожидается.

### `договоры`

Описывает проекты/договоры и правила выплат.

Основные колонки:

- `код` — уникальный код договора, который используется во всех остальных листах.
- `название`, `номер` — справочные поля для отчётов.
- `тип договора` — например `госзаказ`, `grant`, `off_budget`, `minprom`.
- `счет` — лицевой счёт/шифр затрат, используется в отчётах и правилах 120.
- `ГОЗ` — признак оборонного заказа. Для таких договоров применяется средний контроль БЭП по штатной части `оклад + 122`.
- `дата начала`, `дата окончания` — период действия договора.
- `фот` — годовой лимит ФОТ договора.
- `оклад разрешен`, `120 разрешена`, `122 разрешена`, `124 разрешена`, `152 разрешена`, `стимулирующая приказом разрешена` — какие виды выплат можно платить с договора.
- `проект Приоритет` — включает специальный режим договора «Приоритет».
- `конечная дата выплат оклада`, `конечная дата выплат надбавок` — крайний срок выплат по видам. Пусто означает срок по дате окончания договора.
- `основное место разрешено`, `совместительство разрешено` — можно ли открывать на договоре основной оклад или совместительство.

Договор с положительным `фот` задаёт доступный лимит/кассу. Если весь ФОТ не удаётся освоить выплатами сотрудникам, расчёт не падает: остаток переносится на конец года и показывается как предупреждение.

### `120_надбавка`

Задаёт обязательные надбавки за работу со сведениями, составляющими государственную тайну.

Колонки:

- `сотрудник` — `код строки` из листа `сотрудники`.
- `договор секретности` — договор, который задаёт период действия секретности.
- `ставка 120` — ставка надбавки, например `0.05`, `5%` или `5`.

Сервис начисляет 120 только в месяцы, когда действует договор секретности, и только с договоров, где такая выплата разрешена правилами.

### `трудоемкость_по_договорам`

Описывает плановую трудоёмкость договора в чел.-мес. и, если нужно, должность или окладную группу этой строки.

Колонки:

- `договор` — код договора.
- `год` — год планирования.
- `трудоемкость` — план в чел.-мес.
- `должность` — опциональная должность строки трудоёмкости.
- `страница` — страница/пункт положения для задания окладной группы без конкретной должности.
- `номер группы` — номер группы.
- `номер уровня` — номер уровня.
- `средняя стоимость выполнения работ в месяц` — плановая средняя стоимость одного чел.-мес.

Если должность задана, строку могут закрывать сотрудники с этой должностью или из той же группы взаимозаменяемости. Если должность пустая, но заполнены `страница`, `номер группы`, `номер уровня`, строку может закрывать любая должность из этой группы. Если не задана ни должность, ни группа, строка становится общей потребностью договора. Факт по трудоёмкости считается по открытым ставкам и выплатам на договоре.

Сервис контролирует:

- факт чел.-мес. против плана;
- сумму выплат против плановой суммы;
- среднюю стоимость выполнения работ;
- компенсацию между строками внутри одной группы взаимозаменяемости.

### `фот_по_месяцам`

Задаёт помесячные поступления по договорам.

Формат: первая колонка — договор, далее месяцы `1`...`12` или русские сокращения месяцев.

```text
договор | 1       | 2 | ... | 12
C001    | 1200000 |   | ... |
C002    |         |   | ... |
```

Пустая ячейка означает отсутствие поступления в этом месяце. Если `фот_по_месяцам` отсутствует, сервис может разнести поступления автоматически по правилам договора.

Фиксация ячейки поддерживается несколькими способами:

- заливка ячейки в Excel;
- суффикс `*` или `!` в значении, например `2000000*`;
- дополнительный лист `фиксация_фот_по_месяцам` в расширенном режиме.

### `настройки`

Задаёт год и веса оптимизации.

Основные параметры:

- `год` — год планирования.
- `разрешить дефицит` — можно ли вернуть частичный план с дефицитами вместо полной невыполнимости.
- `макс договоров оклада в год` — сколько договоров-источников оклада допустимо для сотрудника за год.
- `штраф смены договора оклада` — насколько дорого менять источник оклада.
- `штраф административной сложности выплат` — штраф за лишние связи сотрудник-договор и смены схемы.
- `штраф отклонения от равномерного освоения` — штраф за неравномерное расходование ФОТ.
- `штраф использования приказа` — стимулирующая приказом считается крайним инструментом.
- `допуск трудоёмкости` — допустимое отклонение по трудоёмкости.
- `штраф отклонения трудоёмкости` — вес мягкого отклонения по трудоёмкости.

Открытые ставки сейчас включены всегда; отдельная колонка для их включения не нужна.

### `лимиты_по_должностям`

Единый справочник должностей, групп взаимозаменяемости и лимитов.

Колонки:

- `должность` — каноническое название должности.
- `категория персонала` — категория ШР.
- `страница` — страница/пункт положения.
- `номер группы` — номер группы.
- `номер уровня` — уровень/разряд/категория должности.
- `оклад` — справочный оклад за 1 ставку.
- `П2556` — лимит по приказу 2556.
- `П4` — лимит П4.
- `БЭП` — средний лимит штатной части `оклад + 122` для ГОЗ; если заполнен в нескольких строках, используется минимальное положительное значение.
- `примечание` — пояснение.

Если этот лист есть, он является основным источником справочника должностей. Если его нет, используются дефолты из кода.

## Как Работает Совместимость Должностей

Сервис использует одно правило совместимости для строк `трудоемкость_по_договорам`:

1. Если в строке не указана ни должность, ни группа, подходит любой сотрудник.
2. Если должность сотрудника совпадает с должностью строки, сотрудник подходит.
3. Если должности разные, но совпадает группа взаимозаменяемости, сотрудник подходит.

Пример: на гранте нужна должность `программист`, а Иванов в штатке `инженер 1.0`. Если обе должности входят в группу `инженерно-технические специалисты`, оптимизатор может открыть Иванову совместительство `0.5 программист` на гранте. В кадровой детализации это будет отдельная строка назначения, а основная строка `Иванов 1.0 инженер` останется отдельно.

Если договору не важна должность, в результате сохраняется штатная должность сотрудника.

## Открытые Ставки И Совместительство

Сервис выбирает открытую ставку по сотруднику, договору и месяцу. Шаг ставки — `0.25`.

Базовые правила:

- основная ставка сотрудника сохраняется как входная штатная ставка;
- дополнительная ставка может открываться как совместительство;
- обычный сотрудник может иметь суммарно до `1.5` ставки;
- совместительство ограничено до `0.5` ставки;
- для студентов и отдельных категорий ограничения жёстче;
- договор может запретить основное место или совместительство.

Оклад на договоре связан с открытой ставкой: если ставка открыта, по договору должен быть возможен оклад.

## Лимиты И Выплаты

По каждому активному сотруднику в месяце сервис старается закрыть полную месячную `зарплату` из входного файла.

Выплаты делятся на:

- `оклад`;
- `120` за гостайну;
- `122` за качество;
- `124` за интенсивность;
- `152` за дополнительную работу;
- `стимулирующая приказом`.

Договоры управляют тем, какие виды выплат разрешены. Лимиты по должностям применяются к штатной части и приказным ограничениям согласно правилам в коде. Если оклад не может закрыть всю сумму, сервис может использовать разрешённые надбавки или приказную стимулирующую, но такие решения штрафуются в целевой функции.

## Касса И Освоение ФОТ

Касса договора считается помесячно:

```text
остаток на конец месяца = остаток на начало + поступление - выплаты
```

Неиспользованный остаток всегда переносится только вперёд, в следующий месяц. Отдельной настройки для отключения переноса сейчас нет.

`фот_по_месяцам` задаёт поступления вручную. Положительный `фот` договора задаёт общий лимит выплат; неосвоенный остаток не блокирует расчёт и подсвечивается экономистам.

Для ГОЗ с признаком `ГОЗ = да` П2556 остаётся индивидуальным максимумом:

```text
оклад + 122 ≤ П2556 по должности сотрудника × ставка
```

БЭП применяется как средний лимит по ГОЗ-договору и месяцу:

```text
сумма(оклад + 122 на ГОЗ-договоре за месяц)
≤ БЭП × сумма активных ставок на этом ГОЗ-договоре в месяце
```

Отдельный сотрудник может получить штатную часть выше БЭП, если средняя по договору удерживается за счёт сотрудников ниже БЭП. Оптимизатор стремится приблизить среднюю к БЭП; если выйти ровно на границу нельзя, минимизируется недобор до неё.

Средняя стоимость из `трудоемкость_по_договорам` не является индивидуальным потолком. Она контролируется отдельно как средняя стоимость строки трудоёмкости.

## Дополнительные Листы

Эти листы не создаются в новом шаблоне, но их можно добавить вручную для сложных сценариев:

- `минимальные_остатки` — минимальный/неподвижный остаток по договору и месяцу.
- `фиксация_фот_по_месяцам` — отдельная матрица фиксации ячеек `фот_по_месяцам`.
- `ручные_назначения` — ручные назначения сотрудника на договор и вид выплаты, с суммой или без суммы.
- `ручные_запреты` — ручные запреты назначений.

Для обычного нового файла эти листы добавлять не нужно.

## Результат Расчёта

Выходной Excel содержит пользовательские отчёты:

- `Как читать файл` — краткая навигация по результату.
- `Итог расчета` — статус, основные суммы и показатели.
- `Проблемы и предупреждения` — что нужно проверить.
- `Выплаты по сотрудникам` — помесячные выплаты сотрудникам.
- `Выплаты по договорам` — помесячные выплаты по договорам.
- `Остатки по договорам` — касса, поступления, расходы, остатки.
- `Освоение план-факт` — план и факт освоения ФОТ.
- `Контроль трудоёмкости` — план/факт чел.-мес., суммы и средние по строкам трудоёмкости.
- `План выплат` — техническая детализация начислений.
- `Выплаты по трудоёмкости` — отнесение выплат на строки трудоёмкости.
- `Контроль должностей` — совместимость сотрудников и строк договора.
- `Административная сложность` — сколько связок и смен схемы получилось.
- `Проверка дробления выплат` — контроль дробления выплат.
- `Смены схемы выплат` — где менялись источники выплат.
- `Дефициты` и `Дефициты по месяцам` — недоплаты, если разрешён дефицит или задача не закрылась.
- `ШР_детализация` — кадровая детализация назначений, включая должность назначения по договору.

## Пересчёт С Фиксациями

После первого расчёта можно открыть результат, зафиксировать строки на листе `План выплат` и передать результат как `--plan`.

```bash
fot-planner solve -i data/input.xlsx -o data/result.xlsx --plan data/result.xlsx
```

Фиксации используются как ограничения для следующего расчёта. Это позволяет сохранить ручные решения и пересчитать остальную часть плана.

### Стенд разбора документов

Разбор документов держится на языковой модели, а модель отвечает не так, как
обычный код: другая подсказка, другая схема, другой бюджет ответа — и величина
из соседней ячейки молча пропадает. Заметить это глазами по одному прогону
нельзя. Стенд прогоняет разбор по документам с уже проверенным ответом и
говорит, что разошлось.

```bash
.venv/Scripts/python.exe harness/run.py               # все случаи
.venv/Scripts/python.exe harness/run.py --only uc12   # один, по подстроке имени
```

Случаи лежат в `harness/cases.py`: документ из реестра по имени и что из
него должно выйти — вид, число строк каждой сущности с допуском, строки,
которые обязаны найтись, и сущности, которых быть не должно. Последнее —
главное: ловушки, из-за которых расчёт ГОЗ становится правдоподобно неверным,
выглядят именно так — человек из примера, принятый за сотрудника, перечень
должностей, принятый за штатное расписание.

Код возврата ненулевой, если хоть одна проверка не прошла, — стенд можно
поставить перед выкладкой. Нужен сервер модели, тот же, что у приложения
(из `.env`), и загруженные в реестр документы.

Когда разбор проверен на новом документе, его ожидание добавляют в
`harness/cases.py` — стенд не придумывает правильный ответ, он сторожит уже
проверенный.

Случай с `solves` — сквозная проверка контракта оптимизатора: документ по
шаблону разбирается в чистый реестр в памяти, собирается обратно во входной
файл и решается тем же исполняемым файлом, что и сам документ. Оба обязаны
сойтись. Любая графа, потерянная между реестром и входом — срок договора,
запрет основного места, допуск трудоёмкости, — всплывает здесь как «из
реестра не решается, хотя сам файл решается». `--no-solve` пропускает эти
случаи.

#### Приговоры экономиста как случаи

Строки, вычитанные из документа не по шаблону, лежат отдельно от реестра,
пока экономист их не примет или не отклонит. Каждое решение записывается
приговором (`verdicts`) и становится случаем стенда без ручной работы:
принятая строка обязана извлекаться из этого документа и впредь,
отклонённая — не должна повториться слово в слово. Отклонение и правка в
разговоре о документе попадают ещё и в память агента (`corrections`): при
следующем разборе документа того же вида модель видит их как подсказки.

У каждой предложенной строки есть оценка — «надёжно», «проверить»,
«сомнительно» — и причина. Это не самооценка модели, а проверки по реестру и
справочнику: обязательные графы на месте, оклад в пределах справочника,
договор и сотрудник есть в реестре, должность есть в справочнике, указано,
откуда строка взята. Сомнительные строки в карточке не отмечены заранее.
Оценка записывается в приговор, и стенд каждый прогон печатает калибровку:
сколько «надёжных» отклонили и сколько «сомнительных» приняли. Первое —
знак, что проверки пропускают ошибку, второе — что они слишком строги.

Версия агента (первые семь знаков хеша его подсказок) записывается в каждый
приговор и в каждую работу: когда стенд говорит «сломалось», видно, при
какой редакции подсказок строка ещё находилась.

#### Документы: версии и отпечаток

Повторная загрузка файла с тем же именем — новая версия: прежняя запись
получает состояние «заменён», её строки уходят из реестра и из расчёта, файл
и переписка остаются для истории. Файл, загруженный второй раз без
изменений, версией не становится, а тот же файл под другим именем сервис
называет вслух: у документа записан SHA-256 содержимого. Экономисту он не
показывается — сверять хеш глазами никто не станет, — но лежит в записи
документа и прогона.
