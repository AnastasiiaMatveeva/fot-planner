# fot-planner

Система планирования ФОТ сотрудников по договорам НИОКР (MVP без веб-интерфейса).

Финансисты работают в **Excel**: загружают справочники, запускают расчёт из командной строки, правят план в таблице (`lock=yes` для фиксаций) и пересчитывают остальное автоматически.

## Установка

```bash
cd fot-planner
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

Требуется Python 3.10+. Для MIP используется [OR-Tools](https://developers.google.com/optimization) (решатели SCIP/CBC).

## Быстрый старт

```bash
# 1. Создать шаблон входных данных
fot-planner init-template -o data/input.xlsx

# 2. Заполнить листы employees, contracts, contract_positions, contract_monthly_budget

# 3. Рассчитать план на 12 месяцев
fot-planner solve -i data/input.xlsx -o data/result.xlsx

# 4. В result.xlsx на листе plan поставить lock=yes у строк, которые нельзя менять

# 5. Пересчитать с учётом фиксаций
fot-planner solve -i data/input.xlsx -o data/result.xlsx --plan data/result.xlsx
```

## Листы входного файла

| Лист | Назначение |
|------|------------|
| `settings` | Год планирования, веса штрафов оптимизации |
| `employees` | Сотрудники: оклад, **надбавка**, стимулирующие, ставка, должность |
| `contract_labor` | Плановая трудоёмкость (чел.-мес.); `position` опционально |
| `contracts` | **Все договоры и правила** (перенос, месяцев после окончания, освоение за N дней). Пустые ячейки — дефолт по `тип договора` (в коде: goszakaz, grant, off_budget…) |
| `contract_positions` | Потолок выплаты в месяц по должности на договоре (лимит министерства); назначение сотрудника не ограничивает |
| `contract_monthly_budget` | Поступления (`inflow_amount`); колонка **`lock=yes`** — зафиксированная ячейка (см. ниже) |
| `manual_assignments` | Ручные фиксации (сумма или привязка без суммы) |
| `manual_prohibitions` | Запреты назначений |

## MVP (реализовано)

- Импорт сотрудников и договоров из Excel
- Типы договоров и правила (базово)
- План на 12 месяцев: **оклад** и **стимулирующие** отдельно
- Сроки договоров, должности, ставки, лимиты выплат
- Помесячные **поступления** и **перенос остатков** между месяцами (по типу договора или флагу на договоре)
- Минимизация смены договора для оклада (штраф в целевой функции)
- Ручные фиксации / запреты / lock в плане
- Пересчёт после правок в Excel
- Выгрузка дефицитов и балансов

## Касса договора

**По умолчанию** годовой **`фот`** на `contracts` **равномерно делится** на все месяцы года, когда договор активен: от **даты начала** до **конца** с учётом **`месяцев после окончания`** (0 / +2 / −20 дней для освоения).

Лист **`fot_matrix`** не обязателен — только если нужно **вручную** переопределить поступление в отдельных месяцах.

По договору с переносом (грант, Минпромторг):

```
в январе: поступление = доля годового ФОТ за этот месяц
в феврале: входящий = подвижный остаток с января + поступление февраля
…
```

В **более ранние** месяцы (март → январь) можно отправить только **подвижную** часть:  
`поступление + переносы с ещё более поздних месяцев − расход − неподвижные` из `min_balance_matrix`.

**Неподвижные не обязаны оставаться на счёте в конце месяца** и **целиком уходят вперёд** в следующий месяц вместе с остатком (`month_transfers` — кто сколько отправил назад).

Касса по договору (если **`перенос остатков` = да** — для любого типа, включая госзаказ):

```
закрытие месяца = остаток на начало + поступление − расход
остаток переносится на следующий месяц
```

Равномерность помесячного расхода **не** задаётся жёстким ограничением. Отклонение от `фот / число активных месяцев` штрафуется параметром `weight_uniform_spend_deviation` (см. settings).

Если **`перенос остатков` = нет** — в каждом месяце отдельно: расход ≤ поступление (+ резерв оклада).

## Пустые ячейки на `contracts`

Если колонка не заполнена, при загрузке подставляется дефолт по **`тип договора`**: **goszakaz** — перенос остатков **да**, освоение за 20 дней; **off_budget** — перенос, +2 мес. после окончания; **grant** / **minprom** — перенос, до `end_date`. Все значения можно явно задать в строке договора.

Резерв под оклады — только `settings` или `резерв оклада` на договоре.

## Трудоёмкость (`contract_labor`)

| Поле | Смысл |
|------|--------|
| `person_months` | План, чел.-мес. за год по договору |
| `position` | Детализация плана (справочно); в модели суммируется с другими строками по договору |

- По каждой строке `contract_labor`: допуск **±`goz_labor_tolerance`** (по умолчанию 5%) от плана по чел.-мес. и сумме — для **всех** типов договоров.
- **Прочие договоры**: отклонение от плана — **штраф** (`weight_labor_deviation`), не жёсткий коридор.

Фактические чел.-мес. = Σ `rate ×` (оклад с договора в месяце) по **всем** сотрудникам на договоре. Строки `contract_labor` по должностям складываются в общий план по договору; должность сотрудника назначение не ограничивает.

**Потолок оклада** (`contract_positions`, только `salary`): для ставки 1.0 — `макс выплата`; для сотрудника — `макс выплата × rate`. Надбавка и стимулирующие этим потолком не ограничиваются. При несовпадении должности — максимум по строкам договора.

## Оклад сотрудника и полная выплата

По каждому сотруднику в месяце (жёсткое ограничение): **Σ всех выплат с договоров** = оклад + надбавка + стимулирующие из справочника.

Срезанный потолком оклад можно компенсировать **надбавкой/стимулирующей** на том же или другом договоре (если вид разрешён); за сумму сверх справочника — штраф `weight_salary_compensation_via_flex`.

Оклад **жёстко** привязан к одному договору в месяце; надбавка и стимулирующие могут распределяться по нескольким договорам (со штрафами дробления и смены схемы в целевой функции).

Лист **`дефициты`**: при успешном расчёте (OPTIMAL) пуст. При невыполнимости ограничений — статус **INFEASIBLE**.

## ФОТ в Excel: матрица (как у финансиста)

**Лист `fot_matrix`** — проекты **по строкам**, месяцы **по столбцам**:

| contract_id | 1 | 2 | … | 12 |
|-------------|---|---|---|-----|
| C001 | 400000 | 400000 | … | **2000000** |
| C002 | … | | | |

Заголовки месяцев: `1`…`12` или `янв`…`дек`.

**Фиксация суммы** — на том же листе `fot_matrix`, без второй таблицы:

1. **Заливка ячейки** (как в Excel: выделили → заливка жёлтым) — сумма не пересчитывается.
2. **Суффикс `*`** в ячейке: `2000000*` или `2000000!` (удобно, если заливку не используете).

В шаблоне `init-template` декабрь по C001 уже с жёлтой заливкой как пример.

Устаревший вариант: отдельный лист `fot_lock_matrix` с `yes` — по-прежнему читается, если нужен.

Если есть `fot_matrix`, он используется вместо длинного листа `contract_monthly_budget`.

## Фиксация ячейки ФОТ (длинный формат)

На листе **`contract_monthly_budget`** в **входном** файле:

| contract_id | month | inflow_amount | lock |
|-------------|-------|---------------|------|
| C001 | 12 | 2000000 | yes |

- **`inflow_amount`** — сколько денег по плану в этом месяце (например 2 000 000 в декабре).
- **`lock=yes`** — ячейка **заблокирована**: расчёт **использует ровно эту сумму** и не должен её менять (при будущих авто-правках сетки такие строки пропускаются).

В **результате** появится лист **`budget_locked`** — список всех зафиксированных ячеек для проверки.

Это фиксация **поступления по договору** в месяце, не блокировка выплат сотрудникам. Назначение сотрудника на договор — лист `plan` с `lock=yes` или `manual_assignments`.

## Стабильность оклада (квартал / год)

На листе `settings` (по умолчанию):

| Параметр | Значение | Смысл |
|----------|----------|--------|
| `salary_lock_within_quarter` | `True` | **Жёстко:** не более **одной** смены договора оклада внутри календарного квартала |
| `max_salary_contracts_per_year` | `2` | **Жёстко:** не более N договоров-источников оклада за год (лучше 2–3, не 1) |
| `penalize_quarterly_salary_switch` | `True` | **Мягко:** штраф за каждую смену оклада между месяцами (`salary_change`); 0 смен за год — идеал |
| `weight_salary_switch` / `вес штрафа смены оклада` | `500000` | Сила штрафа смены оклада в целевой функции |
| `weight_uniform_spend_deviation` / `вес отклонения равномерного освоения` | `50000` | Штраф за отклонение **фактического** месячного расхода от `фот / число активных месяцев` **сверх допуска** (1000 ₽ или 1% от идеала). Вес умножается на **долю** отклонения: `(факт − идеал) / идеал`, не на рубли |
| `weight_allowance_switch` / `вес штрафа смены надбавки` | `300000` | Штраф за смену договора **надбавки** между месяцами (`flex_change`, как `salary_change` для оклада) |
| `weight_incentive_switch` / `вес штрафа смены стимулирующей` | `300000` | То же для **стимулирующей** |
| `weight_allowance_incentive_switch` | (устар.) | Если новые столбцы не заданы — применяется к надбавке и стимулирующей |
| `weight_employee_contract_year_count` / `штраф договора сотрудника за год` | `200000` | Штраф за каждую связку сотрудник–договор, использованную в году (справки) |
| `weight_employee_contract_month_count` / `штраф договора сотрудника в месяце` | `20000` | Штраф за дополнительный договор сотрудника в конкретном месяце |
| `weight_global_contract_count` / `штраф договора в плане` | `50000` | Слабый штраф за число договоров, задействованных в плане |
| `weight_flex_payment_fragment_count` / `штраф дробления надбавок` | `10000` | Штраф за каждый `use` по надбавке/стимулирующей (борьба с 24k+1k) |

В одном месяце оклад сотрудника всегда идёт **только с одного договора**. Надбавка и стимулирующая могут идти с нескольких договоров, если иначе не закрыть сумму или жёсткие ограничения; каждый лишний договор штрафуется в целевой функции. **Смена источника** между месяцами штрафуется отдельно (`flex_change`). Внутри квартала нельзя менять договор **чаще одного раза** (например: апрель–май — внебюджет 3, июнь — внебюджет 10). На границах кварталов смена штрафуется.

Задать цепочку вручную — лист **`manual_assignments`**. Для трёх договоров за год увеличьте `max_salary_contracts_per_year` до **3**.

На листе **`contracts`**: `месяцев после окончания` = `0` (до `end_date`), `2` (+2 мес.), **`-1`** (освоение за 20 дней до окончания). По договору с **`фот` > 0** план обязан израсходовать лимит к сроку (`spend_complete_days_before_end`, иначе `end_date − N дней`, иначе `end_date + months_after_end`). Поступления — авто из `фот` или лист `fot_matrix`.

## Резерв по окладам (длинные проекты)

Если у проекта **больше N месяцев с ненулевым поступлением** (авто-разнесение или `fot_matrix`; по умолчанию N=6, т.е. 7+ месяцев) — **независимо от типа договора**:

- на конец месяца остаток не меньше Σ (оклад × ставка) по назначенным на этот договор;
- оптимизатор **предпочитает** сажать оклады на такие проекты.

Порог **N** — в `settings`, столбец `min_fot_months_for_salary_reserve`.  
На договоре можно переопределить: `require_salary_reserve=yes` / `no`.

## Неподвижные (только для переноса назад) и автопереносы

Лист **`min_balance_matrix`** — проект × месяц. Сумма **неподвижных** в марте (например 200 000): на январь/февраль **нельзя** отправить больше, чем `остаток_после_расхода − 200 000` (т.е. `opening + inflow + transfer_in − spent − 200 000`).

- В **конце марта** счёт **может** быть почти нулевым (если всё потратили).
- В **апрель** уходит **весь** остаток марта, без вычитания 200 000.
- 200 000 — ограничение переноса только для месяцев до марта; не задаёт минимальный остаток на все последующие месяцы.

`movable_balance` в отчёте — сколько **максимум** можно отправить на более ранние месяцы.  
`month_transfers` — что система реально перебросила.

Сейчас сетка **вручную**; позже — авторасчёт по штатке (Σ оклад × ставка).

Лист `contract_monthly_budget`: поле **`inflow_amount`** — поступление в месяце без учёта переноса (перенос рассчитывает модель).
